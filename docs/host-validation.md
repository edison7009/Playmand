## Claude Code：交错存档

- 宿主：Claude Code 2.1.220，Windows；沿用本机配置的第三方模型。这不是 Anthropic 模型专项验证。
- 项目级入口：`.claude/skills/playmand/SKILL.md`；以 `/playmand` 发起正常 `--print` 会话。
- 初始化事件列出 `playmand`，轨迹实际读取排错及验证参考，并采用“每页只合并负责字段”的规则。
- 两项测试分别检查人物页与世界页先后交错保存，从新存储实例重载实际磁盘文件。修复前 2 项失败，修复后 2 项通过，独立复核通过。
- 首轮设置最多 8 轮，宿主在本机 Fact-Forcing Hook 要求下补充事实后完成代码修复；创建验证记录时再次遭拦截，最终 `error_max_turns`，退出 1。
- 因首轮关闭了会话持久化，无法恢复原会话；只做了一次最多 8 轮的新会话补全文档。第二次仍被 Hook 拦截写入并触及轮数上限，退出 1，未生成验证文档。没有关闭 Hook 或无限重试。
- 第二次调用为调查 Hook 读取了测试目录之外的父项目验证文件和用户 Hook 源码，违反测试约定的隔离读取范围；未观察到范围外写入。此偏差保留在结论中，不将隔离执行标为通过。
- 新证据确认 Hook 按会话对首次文件操作要求核验后正常重试，前两次的人工测试预算没有留出足够轮数。最后一次文档补全保留 Hook，配置更充分的轮数及 180 秒墙钟上限，只读取当前目录证据。首次写入按要求受检后，正常重试成功，实际生成验证记录，约 52 秒退出 0。
- 最后一次没有 Bash/Edit 工具，没有修改源码或测试，也未重复执行已通过测试。CLI 传入 `--max-turns 16`，但结果的 `num_turns` 为 26；保留这一计数差异，不宣称实际统计值小于 16。

结论分开记录：**技能发现、参考应用、存档修复和最终交付记录完成；一轮全自动完成及所有调用严格隔离读取未通过。** 前两次失败与范围偏差保留。测试框架需要给既有 Hook 的事实核验和正常重试留出合理预算；本页不代表任意 Claude Code 配置都能自动完成。
