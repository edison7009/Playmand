# 评估 Rust + Bevy 开发能力

0.2.0 的评估重点是 Bevy 代码和游戏结果。以下 A/B 实验尚未运行；可执行 ECS 示例验证 API 行为，不能代替模型收益评估。

使用固定的 Bevy 工程副本、同一模型/工具/提示词/时间预算，A 无技能，B 加载 Playmand，新会话独立开始。保留相同的官方文档和搜索能力，不向任一组透露故障答案。冷构建与热缓存分开计时；条件允许时交替顺序、多次运行。

| 用例 | 任务与起点 | 验收重点 |
| --- | --- | --- |
| B01 新建游戏 | 同一份明确的 2D 动作游戏需求，规定玩法、画面参考和平台 | 使用 Rust + Bevy，功能完整、画面匹配、操作手感；不能只交付立方体小样 |
| B02 版本不匹配 | 固定版本工程中提供一段旧版 API 的场景代码 | 保持依赖版本，正确接入当前场景 API，编译且运行显示模型 |
| B03 查询与时序 | 两个可重叠的可变 Query，以及生成实体后立即消费的实际故障 | 原故障可复现，修复查询语义和命令可见性；不以禁用系统过关 |
| B04 固定步输入 | 不同渲染帧率、零次/多次固定更新下的一次性冲刺 | 不丢按下、不重复冲刺，持续移动与暂停恢复符合设计 |
| B05 GLB 动画 | 模型显示但没有播放动画；再增加独立角色预览 | 当前实例 player/graph 正确，主场景与预览姿态独立，关闭后无无用相机 |
| B06 UI 与重开 | 两次开始/退出/重开后 UI 和关卡叠加 | 控件与关卡唯一，设计要求重置的资源正确，操作和画面通过 |
| B07 玩家包 | 开发目录运行正常，移动包后缺资源 | 新目录启动，模型、纹理、字体、音效和相关流程完整 |
| B08 Blender MCP 资产 | 独立 Blender 场景，制作有开盖动画的宝箱并接入 Bevy | 实际发现 MCP 工具、盖体独立且转轴正确、重复修改无多余副本、保存 blend/GLB、游戏内点击播放动画；检查真实画面 |

B08 尚未执行。两组使用同一 Blender/MCP 版本、相同源场景与资产来源权限；不能给技能组额外工具后把差异归因于技能。缺少 MCP 时可另测 CLI 路径，但不能记作 MCP 测试通过。

每次选与修改条目相关的用例，不为一次小修执行所有实验。记录正确性、构建失败次数、API 猜错次数、耗时、人工接管和实际画面/功能结果。代码更短或多写了报告不能单独证明开发得更好；视觉评价可匿名打乱两组产物，按同一需求评分。

审阅时检查：未指定引擎的新游戏采用 Rust + Bevy；明确指定其他引擎的现有项目不被擅自迁移；已有 Bevy 版本不为套用示例升级；用户要求的规模与风格不被固定“最小循环”削减。没有 GPU 时记录能力缺口，不用构建通过冒充画面验收。

维护经验可参考 [经验筛选](../skills/playmand/references/learning.md)，仅在维护或交接需要时使用。新条目应提供实际版本、错误症状、有效修正和适用边界；优先替换失效指导，不积累对所有任务生效的流程约束。
