# 评估 Rust + Bevy 开发能力

0.2.0 的评估重点是 Bevy 代码和游戏结果。以下 A/B 实验尚未运行；可执行 ECS 示例验证 API 行为，不能代替模型收益评估。

使用固定的 Bevy 工程副本、同一模型/工具/提示词/时间预算，A 无技能，B 加载 Playmand，新会话独立开始。保留相同的官方文档和搜索能力，不向任一组透露故障答案。冷构建与热缓存分开计时；条件允许时交替顺序、多次运行。

| 用例 | 任务与起点 | 验收重点 |
| --- | --- | --- |
| B01 新建游戏 | 同一份明确的 2D 动作游戏需求，规定玩法、画面参考和平台 | 使用 Rust + Bevy，功能完整、画面匹配、操作手感；不能只交付立方体小样 |
| B02 版本不匹配 | 固定版本工程中提供一段旧版 API 的场景代码 | 保持依赖版本，正确接入当前场景 API，编译且运行显示模型 |
| B03 查询与时序 | 两个可重叠的可变 Query，以及生成实体后立即消费的实际故障 | 原故障可复现，修复查询语义和命令可见性；不以禁用系统过关 |
| B04 固定步输入 | 不同渲染帧率、零次/多次固定更新下的一次性冲刺 | 不丢按下、不重复冲刺，持续移动与暂停恢复符合设计 |
| B05 GLB 动画 | 模型显示但没有播放动画；再增加独立角色预览 | 当前实例 player/graph 正确，主场景与预览姿态独立，关闭后无无用相机 |
| B06 UI 与重开 | 两次开始/退出/重开后 UI 和关卡叠加 | 控件与关卡唯一，设计要求重置的资源正确，操作和画面通过 |
| B07 玩家包 | 开发目录运行正常，移动包后缺资源 | 新目录启动，模型、纹理、字体、音效和相关流程完整 |
| B08 Blender MCP 资产 | 独立 Blender 场景，制作有开盖动画的宝箱并接入 Bevy | 实际发现 MCP 工具、盖体独立且转轴正确、重复修改无多余副本、保存 blend/GLB、游戏内点击播放动画；检查真实画面 |
| B09 网页特效 | 现有 React/Tauri 页面，要求加入可撕开的卡包和五张全息卡片，不准引入游戏引擎或 JavaScript 3D 库 | 选择 Rust → WebAssembly + WebGL2；页面先显示加载状态，首帧不等全部素材；卡片有厚度、反光并随指针倾斜；页面隐藏时停止绘制、卸载时释放 GPU 资源；按实测写出体积 |
| B10 物理 | Bevy 0.20 项目要求方块堆叠、踩踏板触发开门、子弹不穿墙 | 选用与 Bevy 版本匹配的 Avian（已用 Rapier 则沿用）；Cuboid 用完整长度；事件实体带 `CollisionEventsEnabled`；踏板用 `Sensor`；快速物体开启 `SweptCcd`；用固定时钟的无窗口测试证明落地、触发和不穿透 |
| B11 音频 | Bevy 0.20 游戏要求背景音乐循环、切换关卡时 2 秒交叉淡化、暂停菜单压低音乐、设置里有音乐和音效两个音量滑杆 | 用 bevy_kira_audio 并关掉 Bevy 的 `audio` feature；音量按分贝；淡化用 tween；音乐与音效分声道；不每帧重启音乐；用模拟声卡或真实运行证明淡化和暂停 |
| B12 调试面板 | 给现有 Bevy 游戏加一个可开关的调试面板：显示碰撞体、调时间流速、生成敌人按钮 | bevy_egui 版本与 Bevy 匹配，egui 次版本一致；系统放在 `EguiPrimaryContextPass`；点击面板不触发游戏操作；列表控件 id 不冲突 |
| B13 Macroquad | 用户指定用 Macroquad 做一个打砖块小游戏，要求能发布到网页 | 不引入 Bevy；规则与绘制分离并有无窗口测试；固定步长且限制单帧 dt；能构建 wasm32 并照实写出体积 |
| B14 GPU 计算 | 用 wgpu 在 GPU 上处理一张图片（如模糊）并读回保存 | wgpu 版本与项目一致；读回时按 256 字节补齐每行并去掉填充；`map_async` 后轮询设备；没有 GPU 时给出明确提示而非像代码错误一样失败 |
| B15 升级手感 | 现有游戏的升级只有数字 +1，要求做出有手感的升级、里程碑和满级反馈，且经验不足时只吸收 | 分层且逐级变强；吸收不像升级；预备-动作-跟随；冲击时刻驱动音效；镜头不跟跳；满级不循环；序号防止取消后迟到的完成；减少动态效果只留发光；效果写成可测试的数据 |
| B16 音效电平表 | 用 Kira 0.12.6 做音乐、音效两个分贝滑杆，以及只显示玩家实际听到的音效响度的电平表（MockBackend，固定 API） | 电平表读到滑杆之后的信号（Kira 音轨先跑效果器再乘音量，所以不能挂在音效轨本身）；不含音乐；静音为 0、−6 dB 减半 |
| B17 整套技术栈 | Bevy 0.20 + Avian 0.8 的房间：球落到压力板上开门并用 bevy_kira_audio 播放一次咔嗒声，bevy_egui 调试面板，点面板不开火；起始工程开着 Bevy 默认 feature（含 `audio`），压力板放在地面上 | 关掉 Bevy 的 `audio`；只认球压板（压力板碰地面也会上报）；30–240 fps 下门只开一次、声音只请求一次；点面板不开火；egui 只有一个版本；测试里用输入消息而不是直接改 `ButtonInput` |

B08–B15 尚未作为对照实验执行（B09–B15 的做法已在 `web/` 和各示例中实际做通，但还没有做有无技能的两组对比）。两组使用同一 Blender/MCP 版本、相同源场景与资产来源权限；不能给技能组额外工具后把差异归因于技能。缺少 MCP 时可另测 CLI 路径，但不能记作 MCP 测试通过。

每次选与修改条目相关的用例，不为一次小修执行所有实验。记录正确性、构建失败次数、API 猜错次数、耗时、人工接管和实际画面/功能结果。代码更短或多写了报告不能单独证明开发得更好；视觉评价可匿名打乱两组产物，按同一需求评分。

审阅时检查：未指定引擎的新游戏采用 Rust + Bevy；明确指定其他引擎的现有项目不被擅自迁移；已有 Bevy 版本不为套用示例升级；用户要求的规模与风格不被固定“最小循环”削减。没有 GPU 时记录能力缺口，不用构建通过冒充画面验收。

维护经验可参考 [经验筛选](../skills/playmand/references/learning.md)，仅在维护或交接需要时使用。新条目应提供实际版本、错误症状、有效修正和适用边界；优先替换失效指导，不积累对所有任务生效的流程约束。

**结论**：这三题上技能没有带来可测的正确性差异。对照组先读 `~/.cargo` 中 wgpu 30.0.2、Avian 0.8.0 的源码再动手，接口一次未猜错，也自己找到了行填充、`CollisionEventsEnabled`、固定步长等要点。唯一稳定的差别是 B13 技能组按指南开启体积优化，WebAssembly 小 28%（438 KB 对 608 KB，gzip 152 KB 对 183 KB），但题面未要求体积。另需注意：技能自带的 `gpu-wgpu`、`physics-avian` 示例与 B14、B10 很接近，即使如此也没有拉开差距。

**下一批应选**源码里查不到、或需要判断的题：跨 crate 冲突（bevy_kira_audio 需关闭 Bevy 的 `audio`；bevy_egui 0.43 用 egui 0.36 而非最新）、违反直觉的行为（Kira 音轨先跑效果器再乘音量）、以及靠盲评打分的设计题（B15 升级手感）。

## 2026-11-18 第二批：B12、B15、B16

做法同试点：每题两个全新的子 Agent，同一模型、同一题面，一组先读技能，一组不读；题面不提坑。B12、B16 用隐藏测试判分，并先确认隐藏测试能分出对错：B16 把电平表挂在音效轨本身会挂 3/6，B12 把面板 crate 的 egui 改成 0.35 直接编译失败（类型不匹配）。B15 由第三个不知道来源的 Agent 盲评：先写整体偏好，再按 10 项评分表各给 0–2 分。

B12 两组都在中途遇到 API 限额，续跑后完成；两组共用一个 target 目录，技能组那项时好时坏的测试可能来自两边同名 crate 互相覆盖产物，不一定是代码问题。"点面板不开火"只有各组自写测试，没有隐藏测试。

**结论**：
- **正确性题仍没有拉开差距。** 对照组读了 `~/.cargo` 里的 Kira 和 bevy_egui 源码，自己发现了"效果器先于音量"和"bevy_egui 0.43 用 egui 0.36"，都选对了。只要坑在依赖的源码或 `Cargo.toml` 里能查到，强模型不靠技能也能找到。B16 技能组快约 35%，样本只有一次，只能算方向。
- **设计题出现了真实差异，但不是单向的。** 技能组覆盖了指南里的每一项（下蹲预备、冲击帧、序号取消、减少动态效果），评分表更高；但盲评者整体更喜欢对照组，因为技能组在连续快速喂食时同档会从头重播，冲击点（约 0.29 s）一直到不了：每 0.3 s 喂一次，3 秒涨了很多级却只有 2 次冲击，数字基本不动。对照组用"经验条追赶"，每一级都有自己的弹跳和音效。
- **要改技能**：feedback 指南写了"常见奖励要短到可以连点"，却没说连点时怎么办。应补上：连续触发时不要从头重播；把等级变化排队或像计数器一样追赶，让每一级的冲击都落地；评分时要实测连点节奏，不只看单次动画。

**已做**：feedback 指南（中英文）新增"奖励来得比效果快时"一节和一条常见坑。**下一批**：重跑 B15 看这条是否生效；正确性题改选源码里查不到的知识（平台差异、发布打包、性能取舍），或者干脆承认技能在这类题上的价值主要是省时间、省 token。

技能组用新版指南重新做一次，与上一批同一份对照组方案盲评；这次技能组放在 A 位，评分者不知道来源，并按要求实测连续喂食（每次刚好升一级，持续 3 秒）。

| --- | --- | --- | --- | --- |

| 0.3 s | 2 → 5 | 7 / 11 | 9 | 10 / 11 |

- **评分表：技能组 19/20，对照组 14/20；整体偏好略偏技能组。** 上一批是 19 对 17、整体偏好对照组。
- **修正有效但不彻底。** 不再从头重播，数字不会卡死，冲击从 2 次增加到 5 次；但普通升级 0.7 s 比喂食间隔长，队列又被限制为 2 项，多出的等级合并成迟到的"+6"，每 0.1 s 喂一次时显示落后 16 级，停手后还要约 3 秒。对照组的"经验条追赶"在这一项仍然更好。

**这一轮的总体结论**：在依赖源码能查到答案的正确性题上，技能没有带来可测的差异，最多省一些时间；在需要判断的设计题上，技能让方案更完整（预备、冲击帧、取消安全、无障碍），但也会把指南里没写到的情况做差。评测能发现这些空白，按评测修正指南后，盲评结果从"对照组更好"变为"技能组略好"。样本仍然很小（每题每组一到两次）。

## 2026-11-18 第三批：B17 整套技术栈

题目来自写 [整套示例](../skills/playmand/examples/bevy-stack/src/lib.rs) 时亲手踩到的坑，都只有把几个 crate 放进同一个应用才会出现；题面一个都不提。隐藏测试先验证过能分出对错：参考解全过；不检查是谁压了板会挂"门只开一次"；去掉面板防护会挂"点面板不开火"；开着 Bevy 默认 feature 会被依赖检查发现。验证时还发现隐藏测试自己不公平：bevy_egui 在 `PostUpdate` 才更新"egui 是否要用指针"，测试原来在 `PreUpdate` 就算好，会误判和 bevy_egui 实际做法一致的写法；已改正，已提交的整套示例也一起改了。
