# Playmand 路线图

Playmand 是 AI Agent 用 Rust 做游戏和视觉创作时使用的技能。Bevy 是默认引擎，但技能不绑定 Bevy：Agent 会从一组已经验证过的工具里按任务选择，并且始终尊重用户指定的引擎。

目标不是支持最多的引擎，而是成为 AI 最擅长使用的 Rust 创作技能。所以每个新加入的工具都必须**带一个能运行的例子、锁定版本，并在 CI 里检查**。只有文字说明的工具，不会出现在选择表里。

## 三个领域

| 领域 | 包含什么 | 默认 |
| --- | --- | --- |
| **游戏** | 实时游戏，2D 与 3D，ECS、输入、界面、物理、音频 | Bevy |
| **动效** | 录制动画与视频、生成式视觉、网页和 Tauri 应用里的特效 | Bevy 固定时钟；网页特效用 Rust → WebAssembly + WebGL2 |
| **模拟** | 大量相互作用的物体、粒子、以物理为主的场景 | Bevy ECS + 物理引擎 |

资产制作（通过 MCP 驱动 Blender）和编码（FFmpeg、AVFoundation）服务于这三个领域。

## 加入新工具的规则

1. **能运行的例子**，检查可观察的行为，尽量无窗口运行，放在 `skills/playmand/examples/`。
2. **锁定版本**，与技能的 Bevy 基线兼容，或写明它独立使用。
3. **CI** 在 Windows 和 Linux 上构建并测试。
4. **一份专项资料**，英文为主并附中文副本，只在任务需要时读取。
5. **引擎之间不互相依赖**：Macroquad 项目不引入 Bevy，网页特效不引入任何引擎。
6. **一道评测任务**写进 `docs/evaluation.md`，证明有这份资料时技能做得更好。

## 阶段

### 第一阶段：让 Playmand 成为总入口（已完成）

- [x] 用 Rust → WebAssembly + WebGL2 在网页和 Tauri 应用里做特效，在线卡包见 <https://playmand.com/zh/>，指南见 `references/web-wasm.md`。
- [x] 调整技能和 README 的定位：“Rust 游戏与视觉创作，默认 Bevy”，而不是“一个 Bevy 技能”。
- [x] 在 `SKILL.md` 加入**引擎选择表**：按任务选择，尊重用户指定的引擎。
- [x] **用 Avian 做物理**（为 Bevy ECS 设计的物理引擎）：一份指南，加一个无窗口例子，覆盖碰撞、传感器和确定性；Rapier 作为另一选择介绍。

### 第二阶段：大多数游戏都要用的部件

- [ ] **Kira 音频**（音乐、音效、交叉淡入淡出）。
- [ ] **egui** 做调试面板和游戏内工具。
- [ ] **Macroquad** 做极小的 2D 游戏和最小体积的 WebAssembly。
- [ ] **wgpu** 说明，供网页特效和自定义渲染通道共用。

### 第三阶段：有真实演示需要时再加

Fyrox（完整 3D 编辑器流程）、nannou（生成艺术，加入前先确认维护状态）、Lightyear（多人联网）、Lyon 与 Vello（矢量图形）。每个都随需要它的演示一起加入。

## 不打算做的

- 把多个引擎捆进同一个项目或同一个运行时。
- 用户没要求时把现有项目迁移到别的引擎。
- 在工具还没有例子和 CI 检查前，就把它放进选择表。
