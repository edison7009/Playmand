# 美术方向：先有图，再动手

已验证的部分：[`scripts/cutout.swift`](../../../../skills/playmand/scripts/cutout.swift) 用模拟生成图测试过，背景分别是纯色和渐变；抠出的遮罩与真实透明通道的重合度（IoU）为 0.99，半透明的翅膀和羽毛都保留了下来。本页其余内容是工作流程指引。

对 Agent 来说，代码和引擎是容易的部分：只要有一张"成品应该长什么样"的图，在 Bevy、视频或网页里还原它的布局、配色、光影和特效都很直接。难的是凭文字想象外观，而用代码拼出来的美术（方块、基础图形）很少有完成度。所以做新的视觉作品时，先拿到一张图。

## 什么时候做

外观很重要、又还没有参考图的新视觉作品：新游戏、宣传视频、网页特效、角色、场景。

以下情况跳过，直接开工：

- 用户已经给了参考图、美术素材、风格规范，或者要对齐一个已有项目；
- 任务是修 bug、重构、写逻辑、优化性能，或者在已有外观的项目里加功能；
- 用户说直接做，或者不想出图。这时选一个合理的默认风格，并说明选了什么。

绝不能因为这一步卡住：它是为了避免白做一遍的建议，不是关卡。

## 图从哪里来

用户给了参考图或美术素材，就直接用。否则有四条路可以拿到图；告诉用户适用哪几条，不要替用户选付费的：

1. **宿主自带的生图能力。** 有些 Agent 宿主自己就能生图（比如 Codex），当前会话也可能接入了生图工具或 MCP 服务。先看当前会话能调用什么，能用就直接用。
2. **用户的生图软件。** 写好提示词交给用户：*"我猜你想要的是这种样子，把这段话贴进你的生图软件（Gemini、豆包、ChatGPT、Midjourney……），把满意的那张发给我。"* 这些软件很多是免费的。最简单，也是什么都没配置时的默认做法。
3. **用户接入的生图 API。** 适合批量出图或全自动流程。服务类型有：生图与改图（Google Gemini、OpenAI、xAI 等）、图转 3D 并绑骨骼（Tripo、Meshy 等）、音效与音乐。用户选一家，把 key 设到环境变量里；Agent 读该服务当前的 API 文档后接入。第一次调用前先说明费用，key 不能写进代码或提交到仓库，也绝不替用户注册或付费。

4. **现成的图，找来而不是生成。** 常见的题材（巨型机甲、赛博朋克街道、温馨农场）网上已经有大量图片。请用户自己搜，或者以图搜图，把喜欢的几张发回来；如果当前会话能上网搜索，也可以由 Agent 搜几张，问用户"是你想要的这种感觉吗？"。找来的图**只能当参考**：用来对齐风格、配色、比例和氛围，除非授权允许，否则不能直接放进作品。而且有名有姓的作品（某个机甲系列、某款游戏或某个角色）属于别人：要在同一类型里设计原创的，不能照搬。

无论走哪条路，后面都一样：定风格、做素材、开发，再拿成品和图对比。

## 美术谁来做

先问清作品类型和用户手上的素材：[技能入口](../README.md#先问清用户要什么有什么)按作品类型列出了哪些自己做、哪些要用户提供。

目标图说明成品该长什么样；接下来要决定每样素材从哪里来。每一层都交给最擅长的一方：

| 内容 | 谁来做 | 原因 |
| --- | --- | --- |
| 光影、氛围、天气、粒子、着色器、特效、动作、镜头、UI 动效、数据可视化、生成艺术 | 代码 | 代码做这些又好又原创，运行起来也快 |
| 风格化造型：体素、低多边形、干净的几何或玩具感造型 | 代码 | 形体简单适合代码，风格本身掩盖了没有雕刻 |
| 写实的硬表面：道具、集装箱、建筑、载具、机械、武器 | 代码（配齐整套写实做法），或生成工具 | 代码能做到，但前提是做旧、贴花、损伤、湿润着色、光照和多轮审查都做足：见[让代码做出的 3D 看起来真实](procedural-realism.md) |
| 有机体或细节丰富的角色：人、生物、脸，以及由几百块装甲板组成的主角机甲 | 生成工具（图生 3D、生图）或艺术家 | 用代码拼基础形体，结果像玩具或气球；即使最好的纯代码作品，角色也是这样引入的 |

然后代码用这些素材做它最擅长的事：绑骨骼和摆姿势、动作、光照、特效、镜头、性能、录制和上线。角色要做大动作（转头、抬手、握拳），就用真正的 3D 模型；一张图片只能呼吸、摇晃、被光照亮。

图生 3D 服务（有好几家网页版有免费额度）能把一张图或三视图变成带贴图的 GLB；用户可以像用生图软件一样自己去生成，也可以用 API 接入。之后在 Blender 里整理模型：减面，按关节切开，设置转轴，把手分离出来以便握拳，修好材质（发光部件、湿润效果），再导出给引擎。

## 第 1 步：两三个方向

给出 2–3 个明显不同的方向，每个一句短标签加一段提示词，让用户看图来选，而不是用文字描述：

```text
A. 明亮绘本：手绘奇幻风，暖色日光，柔和阴影，色彩饱满
B. 暗黑水晶：夜景，发光的水晶和符文，深蓝色调，强烈辉光
C. 干净玩具：光滑有光泽的材质，马卡龙色，影棚灯光
```

每段提示词按这个顺序写，用用户的语言（生图软件中英文都能理解，豆包对中文最好）：

1. **是什么、用在哪**："奇幻自走棋游戏的主视觉，从 3/4 俯视角看一个六边形竞技场"。
2. **主体与构图**：画面里有什么、在哪里、镜头角度和距离。
3. **风格**：媒介和质感（手绘、3D 渲染、像素、扁平矢量）、细节程度，参考*类型和氛围*，绝不点名别家公司的游戏、角色或画师。
4. **配色与光线**：3–5 个颜色、时间、主光方向、发光。
5. **格式**：宽高比（场景 16:9、手机 9:16、卡牌 1:1），除非需要，画面里不要文字和 logo。

## 第 2 步：定下风格

选中的图发回来后，仔细看，在项目里写两份东西，之后的每段提示词、每次检查都以它们为准：

- `art/target.png` —— 选中的图本身，原样保留。
- `art/STYLE.md` —— **风格设定**：配色的色值、光线（方向、冷暖、对比）、材质、边缘和描线、细节程度、氛围关键词，以及要避免什么。
- 同一个文件里再写**技术帧**：引擎和 2D/3D、相机视角、原生显示尺寸、资产尺寸、世界缩放、透明、过滤、动画帧、纹理预算、目标平台。生成资产前先锁定这些，素材才不会以错误的尺寸、调色板或格式回来。

## 第 3 步：风格一致的素材

素材的提示词要*附上目标图作为参考*（多数软件支持图加文字），这样素材才是同一家族。各类素材：

- **角色和道具**：一张一个，全身、居中、四分之三侧面，**纯色平涂背景**（选一个主体里没有的颜色），地面不要阴影，不要文字。纯色背景抠图才干净。
- **变体**：先生成一个主角，下一张附上主角图再要："和附图同样的画风和比例，只改：一个穿紫袍的法师"。只描述差异，家族感才保得住。
- **背景和主视觉**：严格按宽高比，重要内容不要放在边缘。
- **图标和小精灵图**：按大尺寸画（512–1024 像素），造型要粗、要简单；缩到 64 像素时细节会糊掉。几个图标排成网格放在一张图里也可以，之后再切开。
- **朝向**：生图模型常把左右弄反；只生成一个朝向，在引擎里镜像。

然后抠图并统一尺寸：

```sh
swiftc -O scripts/cutout.swift -o cutout          # macOS 14+，离线，免费
./cutout art/incoming -o art/cut --trim --pad 16 --max 1024
```

它为每张图输出一个透明 PNG，并打印主体占画面的比例；接近 0% 或 100% 说明抠图失败（背景太花，或主体贴到了边缘），请用户换纯色背景重新生成那张。然后是两道检查，因为文件可能"看起来没错其实错了"：

- **假透明**：一张 RGBA 文件如果每个像素都完全不透明，说明背景被烤进去了，或者透明是假的棋盘格。要拒掉。
- **每个结果都要放到棋盘格或对比色背景上看**，不要用白底，并把整套素材拼成总览图、按真实尺寸一起看过再用。

其他系统上，任何去背景工具都可以按同样的方式使用。

在 `art/README.md` 里维护一份素材清单：名称、文件、**在游戏里的尺寸**（米、像素或秒），并逐项记录来源、授权或生成说明、以及改过什么。没有游戏内尺寸，代码里就会缩放出错；没有来源和授权，就没法发布、也没法重做。

## 第 4 步：开发，再和目标图对比

用素材在引擎里搭出场景，渲染一帧，和 `art/target.png` **并排对比**。逐项写下差距：配色、光线方向和冷暖、对比度、细节、构图、氛围。先修最大的差距，再对比。"能编译""能运行"不是终点，像目标图才是。

引擎能补上静态图做不到的：动作、会动的光、粒子、镜头和节奏。见[游戏手感](feedback.md)和[动态图形](motion-graphics.md)。

## 3D 场景里的 2D 角色

对于只需待机的角色，生成的插画比代码拼出的模型好看。场景可以是 3D 的（棋盘、地形、灯光、粒子、镜头），角色则是抠好的 2D 插画立在其中：一个始终面向镜头的面片，下面一团柔和的影子，一圈轮廓光，再加一点上下浮动和挤压。同一套插画做成全屏切入，技能和胜利画面会很有气势。一张图片可以呼吸、摇晃、被移动的光照亮，但没法令人信服地转头、抬手或握拳，不管是整张变形还是拆成零件：这类动作要用 3D 模型（见[美术谁来做](#美术谁来做)）。

## 常见坑

- 先开发、事后才问外观：整套白做。
- 每个素材都从零写提示词：一个游戏五种画风。要附上主角图或目标图。
- 素材图背景花哨、有渐变或地面阴影：抠图不干净。
- 小图标按小尺寸生成：到游戏里一片模糊。
- 提示词点名别家公司的游戏、角色或画师。改为描述类型和氛围。
- 没记录游戏内尺寸：代码里缩放出错。
- 用代码拿基础形体去雕一个细节丰富的角色或机甲：结果像玩具或气球。模型应该从生成工具或艺术家那里来，力气花在让它动起来、打好光上。
- 让一张平面图做大的 3D 动作（转头、抬手）来冒充 3D：看起来就是剪纸。要用 3D 模型。
