# App 界面升级：给已有应用换新界面

验证来源：同一个 Tauri + React 桌面应用的两次真实升级。

- **第一次**：模型管理和账号管理两页（中间是卡片，右侧是目录）。先和用户在预览页里来回调了大约十五轮，再在应用副本里移植，最后以补丁加交接说明交付。应用自己的类型检查、lint、格式检查和全部测试（202 个文件、3249 项）都通过了。
- **第二次**：直接接手整个应用。在它自己的仓库里把每一页都重新设计了一遍，同时另一个 agent 也在往这个仓库提交。每个问题都先做对比页；每处改动都在浏览器里、模拟掉后端、在真实组件上检查过，再提交到应用的主分支。

[预览套件](../../../../skills/playmand/examples/app-ui-preview/index.html)、[选中与圆角对比页](../../../../skills/playmand/examples/app-ui-preview/states.html)和 [`brand_colour.py`](../../../../skills/playmand/scripts/brand_colour.py) 都来自这些工作。

用户想让已有应用的界面更好看时用本页：卡片、列表、侧边栏、tab、按钮、空状态。设计方法是 Playmand 的：先看图、对比、检查真实结果。代码跟随应用自己的技术栈。React、Vue、Svelte 或纯 CSS 都保持原样，不会为此改用 Rust。

## 先读懂应用

动手画之前，先找出：

- **这一屏背后的组件**：读它们的 props，以及会出现的每一种状态：加载中、空、忙碌、失败、禁用、未安装、被隐私开关遮挡。只照顾正常状态的改版，一用就会出问题。
- **主题**：颜色变量（常见的是 `--bg-surface-rgb` 这类令牌）、圆角、字体、深色和浅色。还要看用户能不能自选主题色。用这些变量来设计，不要另起一套颜色。
- **应用自己的规矩**：通常写在给 agent 或贡献者的说明里，比如“不做自定义悬停提示”“保持系统默认鼠标指针”。预览里也要遵守。
- **这一屏用到的素材**：图标、logo。它们就是美术，不要重画。
- **碰到这些组件的测试**，以及测试靠什么找元素（标签、角色、组件类型、类名）。改之前先跑一遍，之后出现的失败才能确定是自己造成的。本来就失败的测试要记下来，和自己的改动分开报告。

## 先看图，在预览页里定稿

从目标画面开始：用户截一张自己喜欢的界面，就是最好的需求。然后在动应用之前，先做一个**独立的 HTML 预览页**：

- **用应用真实的样子。** 把应用的主题变量复制进去，用应用真实的图标和名称（仓库里常常就带着目录文件），深色和浅色并排显示。如果用户能自选主题色，再放两三种主题色：在橙色上好看的底色，换到绿色上可能就发闷。
- **每次都把现状作为其中一版。** 用户真的会选它。第二次升级里，好几次用户在所有新版本里选了原版：一个动效、一种颜色、一行延迟显示。
- **方向没定时，给三到四个版本。** 并排给用户挑，再细化选中的那一版。看图挑选很快，看文字描述挑选很慢。
- **一个问题一页。** 每页以它的问题命名（比如选中样式、tab 样式、终端样式），每个选择都能随时刷新查看。
- **用户要对比时，先做页面再写代码。** 用户说“先别改，做个网页”时，停下应用里的改动，先做对比页，即使你心里已经有了偏好。
- **每轮只改一两处**，并说明改了什么。会有很多小轮次：高度、重叠多少、悬停移动多少、哪些标签要留。在预览里改一次几秒钟，在应用里改一次要几分钟。
- **每轮自己先检查。** 每一轮都要能刷新看到最新效果（迭代时绕过模块缓存）；告诉用户好了之前，自己先截图看过。

[预览套件](../../../../skills/playmand/examples/app-ui-preview/index.html)是一个起点：顶部是主题变量，底部是示例数据，中间一组卡片、侧边一叠卡片。[states.html](../../../../skills/playmand/examples/app-ui-preview/states.html) 把三种选中样式和两种圆角处理，放在三种主题色下并排对比。用 `python3 -m http.server` 在这个文件夹里启动服务，这样才能读取图标取色。

## 验证过的做法

**从图标取品牌色。** 给每个厂商的卡片配上它自己的颜色，从它的图标里读：

- 取最主要的饱和色相，白、黑、灰像素不参与。
- 把明度和饱和度收进一个白字在所有品牌上都看得清的区间。
- 再继续加深，直到白字对比度达到 3:1（WCAG 大字标准）。
- 黑白 logo 用中性的石板灰卡片。

不需要维护配色表，远程列表里新增的条目也会自动上色。在应用里，这一步在浏览器里读取图标像素完成（[`brand.js`](../../../../skills/playmand/examples/app-ui-preview/brand.js)）；`scripts/brand_colour.py icon.png icon.svg` 在命令行里给出同样的颜色，可以用于设计说明或静态配色表。SVG 按文件里声明的颜色计数，而不是按覆盖面积，所以多色 SVG logo 的结果可能和浏览器里不同。

**一排卡片要安静。** 卡片超过三四张时，满幅品牌色会很吵。

- 卡片大部分保持普通底色，品牌色从一个角透出来（深色约 22%，浅色约 14%）。
- 每张卡片都认得出来，一整排又很安静。
- 角落里的淡 logo 可以在悬停时转正。列表行里不要放同样的淡 logo：在那里它只是噪音。

**彩色卡片上的可读性。** 卡片一旦带上品牌色，在灰底上好用的规则就会失效：

- 数字保持正文颜色，含义交给进度条（绿、黄、红）。绿色卡片上的绿色数字会消失。
- 危险值变成白字红底的小徽章，在任何品牌色上都清楚，包括红色和橙色卡片。
- 透明底上的单色 logo，在同色卡片上画成白色，否则会消失（红色标志放在红色卡片上）。多色 logo 和自带底色方块的 logo 保持原色。
- 黑白 logo 跟随主题：深色主题白色，浅色主题黑色。
- 每一轮都检查两种主题。深色里浓郁的底色，在浅色里可能发闷，浅色要用更淡的底色。

**选中不用高亮边框。** 连着选中好几项时，主题色描边会显得一闪一闪。两种更安静的选中状态经过了检验：

- **带底色的行**：选中的行换成明显更深、均匀的底色，不描边。
- **中性的行**：胶囊和列表行从顶边透进一点柔光，整体再提亮一点。浅色主题里只有光几乎看不出来，所以选中的行还要明显深一档。

同一类元素在整个应用里只用一种选中样式：账号胶囊、对话列表行、添加按钮最后都用了同一种。不要让某一页还留着主题色描边。

**悬停时什么都不能动。** 一像素的位移用户也会马上看到。

- 悬停只改颜色、阴影或一层罩色（`box-shadow: inset 0 0 0 999px rgb(255 255 255 / .04)`），不改边框粗细、内边距或字重。
- 在某些状态下会隐藏的元素，用 `visibility: hidden` 保住它的位置，旁边的元素就不会滑动。
- 卡片在做动画时，角上的图标要固定不动（见下面的坑）。

**只有悬停才有动效。** 悬停会上浮的卡片，点击时不要再弹一下、按下去或者换图标。点击抽卡式的卡片，把条目加进去，卡片本身保持不动。防连点用 ref 里的锁，不要禁用整个列表：禁用会让列表变暗并重新渲染，看起来就是一闪。

**圆角成一家。** 一个形状嵌在另一个里面时（凹槽里的键帽、条里的按钮），内圆角等于外圆角减去间距：9px 的凹槽、内缩 3px，键帽就是 6px，两条弧线同心。嵌套时用相同的圆角反而不对劲。

**控件用同一种字体。** tab、页面按钮、卡片操作用同一种字体和字重。某个按钮上残留的等宽字体会很扎眼。

**改完一处，扫一遍所有页面。** 用户认可了某个区域的样子（右侧列表、添加按钮、选中状态）之后，找出其他页面上同一类区域，一起改齐，再说做完了。用户会找到你漏掉的那一页。

**目录用堆叠卡片。** 侧边“可添加的厂商”列表：

- 整宽的品牌色卡片。每张卡片的下沿（7px）压在下一张下面；最后一张没有隐藏的下沿。
- 悬停的卡片只上抽一点（3px）。下面藏着的部分没有内容，抽多了什么也露不出来。
- “添加”是这叠卡片里的第一张，用浅色，这样既醒目又不脱离这叠卡片。
- 整张卡片是主操作。次要操作（打开官网、取消、切换地区）是叠在上面的独立按钮，绝不做成按钮里套按钮。

**堆叠卡片上的状态。**

- **忙碌**：一道光扫过，显示倒计时，出现一个小的取消按钮。
- **未安装**：卡片变灰并写明。
- **可选项**（地区、服务商）：卡片上的一个小胶囊，里面保留应用原来的切换按钮。

**用户要求保留的文字。** 用户会注意到少了的信息。改版去掉字段标签，或者把两个字段挤到一行，多半会被要求加回来。可以先给更简洁的版本，但标签要随时能加回来。

## 移植进应用

有两种工作方式，由用户决定用哪种。

**在副本里改，以补丁交付。** 应用属于别人，或者用户想先审一遍时用这种。

- 在应用的副本里改。
- 在副本里先提交一个基线，这样补丁只包含这次的改动，用户原来未提交的改动也算在基线里。

**直接在应用自己的仓库里改。** 用户把应用交给你时用这种。

- 提交到用户指定的分支，用户说提交才提交；没让推送就不推送。
- 如果别人（人或另一个 agent）也在改同一个工作区，只暂存自己的改动。用 `git add -p`；拆不干净的文件，用 `git hash-object -w` 写出想要的版本，再用 `git update-index --cacheinfo` 暂存。
- 用自己的名字提交。被要求提交别人的工作时，作者写成对方。
- 如果别人的提交推翻了用户认可过的样子，告诉用户，让用户选，不要悄悄改回去。

两种方式都要：

- **只改外观，不改行为。** props、处理函数、无障碍名称、禁用和忙碌规则都不变。
- **样式放在共用的地方。** 写进样式表或应用的工具类，用主题变量。做一个小的共享组件（堆叠卡片、带底色的行），比把同样的标记复制到好几页里更好。
- **测试依赖的结构要保留**（比如每行一个带标签的 `section`、测试读取的类名）。只在改动是有意为之的地方更新测试，并说明原因。
- **按仓库自己的配置格式化。** 先确认仓库的格式化配置已经在，再运行格式化工具；保持原来的行尾（有些仓库用 CRLF）；交付或提交前，检查 diff 里有没有纯格式化造成的噪音。
- **跑应用自己的检查**：类型检查、lint、格式检查、全部测试。

## 在浏览器里检查真实应用

预览页展示的是设计；只有真实组件才能说明移植做成了什么样。把应用前端放在浏览器里跑、后端模拟掉，用它作为主要的检查手段，而不是只在最后截一张图：

- **模拟后端。** 把应用的后端调用（Tauri 里是 `invoke`）换成一个小的模拟，从示例数据里返回结果。改过的每种状态都配一份示例数据：空、很多条、调用失败、忙碌中。
- **加一个翻页函数。** 在这个环境里加一个小小的 `window.go('页面名')`，点击对应的导航按钮，这样每次检查都从一个确定的页面开始。
- **先量，再看。** 读计算后的样式和 DOM，确认哪些样式真的生效了；颜色用像素取样来确认。动效要逐帧记录元素位置，跳变会在数据里表现为一个很大的步长。
- **让计时器一直跑。** 浏览器面板隐藏时 `requestAnimationFrame` 会暂停，画布绘制和过渡都会停，检查可能卡住。只在这个检查环境里，把 `requestAnimationFrame` 改走 `setTimeout`。
- **改完先刷新再相信。** 每次改动后重新加载或重启这个环境，两种主题都要看。

## 交付

在副本里完成的工作，交付**补丁和交接说明**，不直接在应用的仓库里提交。说明里写清楚：

- 每个区域改了什么，有哪些有意的行为差异；
- 应用命令和测试结果；
- 真实组件的截图；
- 没能验证的部分，比如各平台的真实桌面窗口、不支持 `color-mix()` 的旧版 WebView。

对照仓库当前状态试应用补丁（`git apply --check`）。如果期间已经有人应用了旧版本，就补一个增量补丁，而不是重新出一个完整补丁。

直接在应用仓库里完成的工作，说明写进提交信息和给用户的汇报里：改了什么、提交号、跑了哪些检查，以及哪些失败本来就存在。

## 踩过的坑

- 颜色写成 `hsl(220 9% 30%)`，标记里出现了“%”，一个检查卡片上不能出现假“0%”的测试因此失败。颜色要写成 `rgb()`。
- 浅黄色品牌生成的卡片太亮，白字看不清，加了对比度加深这一步才解决。
- 在复制仓库的格式化配置之前就运行了格式化，项目里写在一行的代码被折成了多行；之后用正确配置再跑一次也恢复不回来。
- 一个脚本用 LF 重写文件，CRLF 仓库里的文件每一行都变成了改动。
- 堆叠卡片上的链接按钮调用了 `event.stopPropagation()`，测试直接调用 `onClick()` 不传事件，于是失败；同级按钮本来就不需要它。
- **WebKit 悬停时的错位（在 macOS WKWebView 上遇到）：**
  - 悬停时加 `filter: brightness()`，WebKit 会把卡片上的文字和图标重绘到偏了零点几像素的位置，看起来像在滑动。改用内阴影罩色来提亮。
  - 子元素在自己的图层上做动画时（比如转动的 logo），WebKit 会忽略父元素的 `overflow: hidden`。`clip-path: inset(0 round 12px)` 在所有引擎里都能裁住。
  - 其他子元素也要固定在自己的图层上（`transform: translateZ(0)`），否则旁边元素做动画时它们会跟着挪动。
- **滑动的 tab 指示块没有滑，而是跳了过去。** 原因有两个：
  - 某个 tab 下有一个按钮会消失，导致整组按钮移位。用一个隐形占位解决。
  - 组件在第一次绘制前被重新挂载了好几次，每次挂载都记住了目标位置。应该记住上一次画出来的位置，而不是目标位置。
- 测试里模拟的 `getComputedStyle` 只返回部分属性。读取计算样式的辅助函数要能接受 `undefined`。
