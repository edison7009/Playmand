# 动态图形与视频制作

验证来源：[视频示例](../../../../skills/playmand/examples/motion-video/src/lib.rs)。同一份时间线用 Bevy 0.20.1 离屏渲染出一条 9 秒宣传片（标题、数据故事、结尾卡），输出 16:9、9:16、1:1 三种画幅，带音轨、SRT 字幕，并编码成 MP4，在 macOS（Metal）上完成。每个 MP4 都校验了时长、帧数、编码和音轨；解码出的音轨也和画面逐一对照，每个音效都落在对应的帧上，偏差 0 毫秒。时间线、字幕和音轨在 CI 中测试。下文的 ffmpeg 命令没有在这次验证中运行。

当需求是给人看的视频时读这一页：产品演示、讲解、数据故事、logo 片头、社交短视频、发布短片。录制本身的做法见[演示动画与视频录制](video.md)。

## 先选视频类型

| 类型 | 结构 | 时长 | 说明 |
| --- | --- | --- | --- |
| Logo 片头 / 标题 | 标志成形，名字落定，停住 | 3–6 秒 | 常做成无缝循环，放在 README 或网站头部 |
| 产品演示 / 发布 | 问题 → 产品 → 关键时刻 → 行动号召 | 15–60 秒 | 用真实界面截图或忠实的界面示意；一个镜头只讲一件事 |
| 讲解 / 教程 | 按顺序的步骤，每步一句字幕 | 30–120 秒 | 字幕说出这一步，画面演示这一步 |
| 数据故事 | 一个观点、一张图、数字落定 | 5–20 秒 | 在画面上注明数据来源；动画朝着要说明的结论走 |
| 社交短视频 | 第一秒抓人，竖屏 | 6–30 秒 | 字幕烧进画面：很多人静音观看 |

动手前先补齐缺的信息：要传达什么、给谁看、发到哪里（决定要哪些画幅）、多长、品牌包，以及视频里可以出现哪些事实。

## 参考已有视频来做

用户给了一条要模仿的视频时，写时间线之前先把它拆开：

1. 按固定频率抽帧（`ffmpeg -i ref.mp4 -vf fps=4 ref/%04d.png`，macOS 上也可以用 AVFoundation），带着时间戳逐帧看。
2. 写出分镜：每个镜头的起点和时长、什么在动、怎么缓动、怎么转场、文字放在哪里、声音落在哪里。
3. 用用户自己的品牌包、文案、产品画面和音乐，按这个结构重建时间线。模仿的是节奏和版式，不是别人品牌的 logo、美术、素材或音乐。
4. 把同一时刻的参考帧和自己的帧并排对比，列出仍然存在的差异。

这一节是做法指引，示例里没有包含对照参考视频的步骤。

## 先写时间线

画任何东西之前，先把整条视频写成数据：每个镜头的起点、时长和字幕；音效提示点；品牌包。画面、字幕和声音于是只是同一组数字的三种渲染结果，不可能彼此错位。

```rust
pub struct Shot { pub kind: ShotKind, pub start: f32, pub len: f32, pub caption: &'static str }
pub struct Cue { pub at: f32, pub sound: Sound }        // 由镜头推算出来
impl Timeline {
    pub fn opacity(&self, shot: usize, t: f32) -> f32 { /* 交叉淡化 */ }
    pub fn caption_at(&self, t: f32) -> Option<usize> { /* 字幕硬切 */ }
    pub fn cues(&self) -> Vec<Cue> { /* 每根柱子到位时一声"嗒" */ }
    pub fn srt(&self) -> String { /* 字幕文件 */ }
}
```

音效时间要从动画常量推算（`bar_start(i) + BAR_GROW`），不要另外手写一遍。时间线不需要 GPU 就能测试：每一帧恰好有一句字幕，交叉淡化相加等于 1，每个音效都落在对应动作结束的时刻。

## 品牌包

品牌信息集中放在一处：配色（背景、正文、次要文字、线条、一个强调色）、字体、logo、产品名和网址，以及视频里允许说的话。保持品牌一致的规则：

- 只用一个强调色，用在每个镜头真正要讲的那一样东西上（Rust 那根柱子、网址），其余用正文色和中性色。
- 字体：正式交付时，把品牌字体文件随项目一起提供（先确认授权），按句柄加载，这样每台机器渲染出的帧都一样。写成 CSS 字体族列表（`"Helvetica Neue, Arial, sans-serif"`）适合做草稿，但需要开启 Bevy 的 `system_font_discovery` feature，而且效果取决于机器上装了哪些字体。
- 事实和数字必须来自用户或可引用的来源，并在画面上注明（例如"Pereira et al., SLE 2017"）。不要编造统计数字、客户名称或引言。

## 动作与节奏

- 进场用**缓出**，离场用**缓入**，横穿画面用**缓入缓出**。匀速运动显得机械。
- **一次只有一个视觉焦点在动。** 一组元素错开 0.1–0.3 秒依次进场（柱子一根接一根），不要整体一起动。
- **文字停留要够读：** 每个词约 0.3 秒，再加半秒，不要在句子没读完时切走。
- **切镜头用互补曲线的交叉淡化：** 新镜头在旧镜头淡出的同一时间段里淡入，两者相加始终等于 1。如果新镜头自己的入场动画要等到它的起点才开始，交叉淡化期间画面上什么也没有，看起来就是淡出到背景色；入场动画应该在淡入开始时就启动。
- **第一帧就是封面：** 很多平台默认拿第一帧当缩略图，所以第一帧要露出主体，不要是空背景。
- **结尾卡：** 名字、网址或行动号召至少静止停留两秒。
- 数字计数（1.00× → 1.04×）和柱子生长要同时到位，音效也要落在同一帧。

## 发挥游戏引擎的长处

用游戏引擎渲染视频，画面就可以像游戏一样动：有重量、有弹性、有粒子、有扫光、有景深。示例把下面每一种都用上了，全部按帧的时间摆放，所以每次渲染结果完全一样：

- **带弹性的入场：** 标题每个字母一个实体，各自以回弹缓动（`ease_out_back`）升起，带一点逐渐回正的倾斜，彼此错开约 0.05 秒。预热时读取每个字母排版后的宽度（`TextLayoutInfo.size`），再按宽度摆放字母。
- **踩着节拍的粒子：** 标题落定时，20–30 个小圆点带着阻力和一点重力向外迸出，和音效同一时刻。
- **擦除转场：** 每次切镜头，一条强调色的斜色带横扫画面，中心正好在切点，与交叉淡化同时进行，whoosh 音效的峰值也落在这里。
- **会"落地"的图表：** 柱子回弹后停稳，数字跟着柱子计数，网格线逐条淡入，一道光泽扫过关键柱子，关键数值脉冲一次。
- **水波纹与弹出：** 结尾卡的标志弹出，播放三角旋转到位，叮声响起时圆环一圈圈扩散。
- **景深：** 几个又大又淡的圆在所有内容后面缓慢漂移。
- **可复现：** 所有"随机"排布都来自带种子的生成器。种子要先打散：普通 xorshift 用相邻的种子（100、101、102……）时，第一个数几乎相同，示例的背景圆在打散种子之前就全挤在了一侧。

注意分寸：每个镜头只有一个主角动作，动效是为信息服务的，不要喧宾夺主。

## 画幅与安全区

所有画幅都从同一条时间线渲染；排版对准安全区，而不是整个画面。

| 画幅 | 尺寸 | 留空（左、上、右、下） | 常见用途 |
| --- | --- | --- | --- |
| 16:9 | 1920×1080 | 四边各 5% | YouTube、网站、演示 |
| 9:16 | 1080×1920 | 6%、12%、14%、22% | Shorts、Reels、TikTok：平台在右侧放按钮，在底部放文案和账号名 |
| 1:1 | 1080×1080 | 6%、6%、6%、8% | 信息流 |

- 字号按短边计算，9:16 再放大约 30%，因为它是在手机上全屏观看的。标题字号要按安全区宽度封顶，长名字才不会溢出。
- 要改排版，不只是缩放：9:16 下示例把图表标签放到柱子上方，让柱子用满整个宽度。
- 用 H.264 + yuv420p 编码时，宽和高都必须是偶数。

## 字幕

- 社交视频把字幕烧进画面（很多人静音观看）；同时为支持字幕文件的平台（YouTube）输出 SRT。
- 字幕**硬切**，绝不交叉淡化：两行半透明的字幕根本没法读。时间与 SRT 保持一致。
- 字幕放在安全区内，每行约 40 个字符，按安全区宽度自动换行。

## 声音

- 音轨从时间线渲染：一段随视频淡入淡出的背景音乐，加上每个事件对应的音效（切镜头时一声"嗖"，柱子到位时一声"嗒"，结尾卡一声"叮"）。示例用纯 Rust 混音并写出 WAV。
- 归一化到峰值约 -1 dBFS，不能削波。平台会自动统一响度（YouTube 约 -14 LUFS），不要再往上推。
- 配音和有授权的音乐由用户或用户选定的提供方提供，和其他声音一样放到提示点上。不要使用没有该平台授权的音乐。

## 离屏渲染

渲染到图像里，每帧读回一次，这一帧存盘之后时钟才前进。没有窗口，就不会因为窗口被遮挡而出现黑帧，也能在没有显示器的机器上运行。代码和行填充这个坑见 [video.md](video.md#离屏渲染视频推荐用这个)。

## 编码与校验

macOS 不需要 ffmpeg：技能自带的[编码器](../../../../skills/playmand/scripts/encode_mp4.swift)可以输出 H.264 加 AAC 音轨，还能校验成品文件。

```sh
swiftc -O scripts/encode_mp4.swift -o encode_mp4
./encode_mp4 frames/ out.mp4 --fps 30 --mbps 12 --audio soundtrack.wav
./encode_mp4 --verify out.mp4   # 时长、尺寸、帧率、帧数、编码、音轨
```

使用 ffmpeg（未在这次验证中运行）：

```sh
ffmpeg -framerate 30 -i frame-%04d.png -i soundtrack.wav -c:v libx264 -pix_fmt yuv420p -crf 18 \
  -c:a aac -b:a 192k -shortest out.mp4
ffmpeg -i out.mp4 -i captions.srt -c copy -c:s mov_text with-subs.mp4   # 软字幕
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration out.mp4
```

每次导出都要检查成品，不能只看命令有没有成功：

- 时长、帧数、帧率和尺寸与时间线一致；音轨存在，并且和视频一样长。
- 把关键帧拼成总览图（第一帧、每次交叉淡化的中点、每个镜头的高潮、结尾卡），按观众实际观看的尺寸来看。检查有没有空帧、字幕重叠、文字超出安全区或溢出。
- 同步：把音轨解码回来，确认每个音效都落在对应的帧上。

## 常见坑

- 音效时间和动画分开手写，声音和画面越走越偏。
- 字幕交叉淡化，或者同时出现两句字幕。
- 新镜头入场太晚，交叉淡化变成先淡出到背景色。
- 第一帧是空的，却被拿去当封面。
- 一套排版缩放套用到所有画幅：9:16 里字很小、大片留白，或者文字被平台按钮挡住。
- 帧尺寸是奇数（H.264 不接受），或者读回的行填充没去掉，导致 9:16 画面歪斜。
- 画面上出现没有来源的数字或说法。
- 要做淡入淡出的 Mesh2d 图形用 `ColorMaterial::from_color(不透明颜色)` 创建：它会选择不透明的混合模式，之后改透明度不起作用，图形就不会淡出，在每个镜头里都挂着。要自己设置 `alpha_mode: AlphaMode2d::Blend`。
- 重叠的图形深度值相同：绘制顺序没有保证，示例在两次编译之间就变过。给每个图形一个自己的 z 值（`0.5 + i * 0.001`），每次渲染才会完全一致。
