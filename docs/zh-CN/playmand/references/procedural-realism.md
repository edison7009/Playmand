# 让代码做出的 3D 看起来真实

本页是做法指引，本仓库还没有用示例验证。它总结了一类作品为什么看起来写实：完全用代码做出的 3D 游戏，不用生图模型，也不下载素材，每个模型、贴图和声音都是写出来的。用代码做硬表面 3D（道具、建筑、载具、机械、武器）之前先读这一页；什么时候才适合用代码做，见[美术方向](art-direction.md)。

代码做出的 3D 看起来像玩具，通常是因为每个零件都是干净的基础形体，套着单一的平涂材质，打着中性的光。它开始变得真实，是因为身上带着真实物体的痕迹：磨损、污渍、损伤、标记、水，以及有明确来源的光。这些都不需要艺术家，但每一层都要刻意去做。

## 1. 先写建模工具箱，再堆细节密度

先写一个小工具箱，所有东西都用它来搭，这样加细节的成本很低：

- 圆角尺寸可控的圆角方块（要像金属，不能像枕头）、带弧长 UV 的车削体（桶、轮胎、锥桶、管道）、多边形挤出、沿路径扫掠的截面（波纹墙、栏杆、包边）、任意朝向的圆柱、双面的带状面（绑带、线缆）。
- 一个带变换栈（push、pop）的构建器：零件按材质分桶收集，最后每个桶合并成一个网格。会动的零件单独保留。
- 缓存复用：每种道具只做几个带种子的变体（`seed % 4`），用克隆，而不是生成成千上万个独立网格。

然后堆密度。真实物体的零件总是比"够用"更多：面板接缝、螺栓、包边、支架、线缆、通风口、标签。真实的地方总有杂物。最常见的失败就是零件太少、太大、太干净。

## 2. 在几何上做出不完美

完美的形状看起来就是假的。用随机种子加上：

- 凹痕（在桶或面板上径向往里推）、下垂（沙袋、篷布、线缆受重力）、压扁（纸箱）、鼓胀（受压的箱体）。
- 布料用带边缘的高度场做垂坠；线缆用带松弛度的曲线。
- 重复的零件加一点随机旋转和偏移，排成一排时不会像尺子量过一样整齐。

## 3. 把磨损和污渍烤进模型

建网格时，根据噪声和形状把污渍和遮蔽烤进顶点颜色（或贴图）：

- 两三层 3D 噪声，做出斑驳的污渍。
- 越靠近地面越暗、越偏棕（最底下 0.2 米），朝上的面更亮，缝隙和遮挡下方更暗。
- 边沿和接缝处有锈带，多孔材料上有水渍线，顶面有灰。

运行时不花任何代价，对写实的帮助比再加一盏灯还大。

## 4. 贴花与标记

真实的东西都有标签和污迹。用画布或着色器画贴花，以很小的深度偏移贴到表面上：

- 带磨损边缘的模板喷字（重量、编号、警告）。
- 顺着重力沿波纹往下流、从螺栓处淌下的锈迹和污痕。
- 警示条纹、编号，以及你自己设计的标志。

## 5. 会对天气起反应的材质

在引擎的标准材质上打补丁（three.js 用 `onBeforeCompile`，Bevy 用材质扩展），不要从头写一个新材质：

- 湿润：湿的地方粗糙度减半，底色稍微变暗；只在朝上的面（按世界法线判断）加雨珠，带一点法线凹凸。
- 用噪声让粗糙度有变化，高光才会碎开，而不是在完美表面上滑过去。
- 不同的金属表面处理（裸金属、阳极氧化、喷漆、塑料）各有各的外观和磨损。

## 6. 光要从东西上来

- 灯具是发光网格，同时报告真正的光源该放在哪里；场景从一个小光源池里取光放过去（只有最近的几盏是实时的）。
- 灯和发光体用很强的自发光加辉光；雾里的光束用加法混合的光锥，光锥本身关掉雾。
- 一盏带柔和阴影的主光、用雾拉出纵深、色调映射（ACES、AgX 之类），加一点颗粒和暗角。
- 画质分档（低到极高），调节阴影、反射和分辨率。

## 7. 用代码做声音

写实的声音也是写实画面的一部分。把它合成出来（用 Web Audio，或离线生成到缓冲区）：

- 多层滤波噪声做雨、风、海浪，加上几百个随机的小水滴声；雷声是低通噪声加几次轰鸣起伏和一段低频尾音。
- 撞击声由噪声爆发、闷响和共振泛音组成；室内和室外用不同的尾音。
- 主输出链带压缩器和软削波；用自己合成的脉冲响应做卷积混响；3D 声像定位；设置同时发声上限，满了就挤掉优先级最低的声音。
- 长的声音分时间片生成，页面永远不会卡住；离线测试输出（峰值、静音、NaN）。

## 8. 像评审一样检查

- 在代码里内置展示接口：有名字的机位（侧面、特写、远景）、固定曝光、能冻结或预先模拟会动的东西，这样任何视角都能随时渲染出来检查。
- 记录每个素材的开销（三角面、网格数、绘制调用）。
- 把这些机位渲染出来，和目标图并排，列出看起来假的地方：太干净的表面、悬空或互相穿插的零件、重复的图案、平的光。先修最大的问题，再渲染一次。
- 更好的做法是让一个没参与制作的评审来看这些截图；自己给自己打分，总是会过早停手。

## 9. 如实估算成本

这种程度的写实需要很多小时的迭代，不是一遍就成：那些有说服力的公开作品都连续跑了好几个小时，用掉了上亿个 token。开工前先告诉用户成本，并把范围控制得很小（一个地点、几种东西），细节才能做深。

## 代码不擅长的

有机体角色、人脸、生物、穿着衣服的人，用基础形体搭出来还是不对。这些从生成工具（图生 3D、生图）或艺术家那里拿，再用代码绑骨骼、做动作、打光、布置镜头：见[美术方向](art-direction.md#美术谁来做)。
